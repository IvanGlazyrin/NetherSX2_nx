## 2024-06-11 - C++ string_view Refactoring Hazards
**Learning:** Refactoring C++ functions to accept and return `std::string_view` requires extreme caution when dealing with temporary `std::string` objects (like those returned by `.substr()`). A `std::string_view` must never be bound to a temporary string that will go out of scope at the end of the statement, as it results in a Use-After-Free (UAF) vulnerability. Additionally, assigning a `std::string_view` pointing to a string back to the same string variable causes undefined behavior due to overlapping memory.
**Action:** Always wrap the source string in a `std::string_view` before performing operations like `substr` if the goal is to extract a view, e.g., `std::string_view(my_string).substr()`, rather than extracting a temporary string first. Force explicit `std::string()` construction when saving a view into a string variable.
