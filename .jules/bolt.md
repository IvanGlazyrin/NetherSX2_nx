## 2024-05-24 - string_view Refactoring for String Parsing in C++
**Learning:** Returning `std::string` by value and repeatedly taking `.substr()` during parsing (e.g., in `trim_copy` and `Trim`) results in many temporary string allocations, which degrades performance when dealing with file I/O operations (like reading ini files or large cheat files). Refactoring to `std::string_view` allows zero-copy substrings, but care must be taken to explicitly construct `std::string(view)` at the final destination where string ownership is actually required to avoid dangling references to local buffers like `char line[4096]`.
**Action:** When implementing parsing functions, explicitly use `std::string_view` parameters and return values instead of `std::string` passed by const reference or returned by value. Only construct `std::string` right before inserting into maps or modifying the underlying data.
