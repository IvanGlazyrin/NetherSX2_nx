## 2024-06-25 - Avoid String Allocations in Trimming
**Learning:** Returning `std::string` copies in trim functions without a fast-path return (`if (first == 0 && last == value.size() - 1) return value;`) causes unnecessary heap allocations for strings longer than SSO (Small String Optimization) limit, even when no trimming is needed. Additionally, passing `string.substr(offset)` instead of adding an `offset` parameter to the target function creates a duplicate allocation prior to passing.
**Action:** When implementing trim or search functions, always check if the original boundaries can be returned directly instead of unconditionally returning `.substr()`. Furthermore, pass string references and offset markers down the call chain rather than eagerly generating substrings at intermediate levels.
